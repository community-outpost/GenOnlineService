# Database schema v1

Status: **draft, reviewed by the release session, topology decided** (one database per environment). Greenfield: the new schema starts clean, and `GenOnlineService import` converts the old production database into the prod environment. Nothing is built. Target location once agreed: `docs/schema.md`.

Companion docs: `identity-openiddict-design.md`, `api-tokens-design.md`, `api-v1-gitlab-model.md`.

## 0. Decisions

- **Both providers stay:** MySQL/MariaDB and PostgreSQL, one EF model, one migration set per provider.
- **One database per environment**, holding account tables and game tables. Environments share nothing; the official deployment ties them together only through Keycloak sign-in.
- **Ids kept** on import into prod: `users.id` is today's `user_id`, match ids are kept.
- **The old schema is only read**, by the import tool. No compatibility views, no `_v2` tables.

## 1. Conventions

| Rule | Example |
|---|---|
| snake_case, plural table names | `match_players`, `friend_requests` |
| Primary key `id` (bigint identity) unless a natural key is the identity | `user_roles` pk `(user_id, role)` |
| Foreign keys `<entity>_id` | `match_id`, `user_id` |
| Timestamps `*_at`, UTC, microsecond precision | `created_at`, `expires_at` |
| A time instead of a flag where the time is useful | `revoked_at` instead of `is_revoked` |
| Enums as short lowercase strings, validated in code | `state = 'active'`, `restriction = 'chat'` |
| No numbered columns; repeated things are rows | `hwid_0..5` → `devices`, `member_slot_0..7` → `match_players` |
| JSON only for genuinely open structures | per-match stat blobs, audit details |
| Calendar keys include the year | `period_start date`, never `day_of_year` alone |
| No version suffixes | no `_v2`, no `new_` |
| Reasons are `varchar(512)` everywhere | bans, roles, audit (`ModerationManager.MaximumReasonLength` and the CLI raised to 512) |

### Portability (MySQL and Postgres)

| Topic | Rule |
|---|---|
| Time | `datetime(6)` on MySQL, `timestamptz` on Postgres, written as UTC by an EF converter |
| JSON | `json` on MySQL, `jsonb` on Postgres, through EF value converters; no provider-specific operators outside one repository class |
| Case-insensitive uniqueness | a `*_normalized` column (upper-invariant, NFKC) with a plain unique index |
| Partial unique indexes | not used |
| Unsigned integers | not used; bigint for ids and counters that may grow |
| Text | `varchar(n)` with explicit lengths, `text` only for free text, utf8mb4 on MySQL |
| Identity | bigint identity (`AUTO_INCREMENT` / `GENERATED BY DEFAULT AS IDENTITY`) |
| Migrations | one set per provider, generated from one model, CI applies both to empty containers |

## 2. Tables

### Accounts

```
users
  id                      bigint pk              -- the user id
  username                varchar(32)            -- display name
  username_normalized     varchar(32) unique
  email                   varchar(254) null
  email_normalized        varchar(254) null unique
  email_confirmed_at      timestamp null
  password_hash           varchar(255) null      -- null without local passwords
  security_stamp          varchar(64)
  state                   varchar(16)            -- active | blocked | deactivated
  two_factor_enabled      bool
  lockout_end_at          timestamp null
  failed_sign_in_count    int
  created_at, updated_at, last_sign_in_at, renamed_at null

user_username_history     id, user_id, username, changed_at, changed_by
identities                id, user_id, provider varchar(32), extern_uid varchar(128),
                          extern_username varchar(128) null, created_at, last_used_at
                          unique (provider, extern_uid)
user_authenticator_keys, user_recovery_codes                   -- TOTP (ASP.NET Identity)
oauth_applications, oauth_authorizations, oauth_scopes, oauth_tokens   -- OpenIddict, renamed via its options
```

### Moderation and audit (shapes agreed with the release session)

```
user_roles
  user_id, role varchar(32), source varchar(32) ('local' | 'upstream:keycloak' | ...),
  granted_by varchar(64) null, granted_at, reason varchar(512) null
  pk (user_id, role, source)

bans
  id, user_id, restriction varchar(16) ('play' | 'chat'), source varchar(32),
  reason varchar(512), created_by varchar(64) null, created_at, expires_at null,
  revoked_at null, revoked_by varchar(64) null, revoke_reason varchar(512) null
  -- several active bans per user allowed; the longest lasting decides what the player sees

audit_log                 -- append-only, no retention purge
  id, created_at, actor_kind varchar(16) ('user' | 'cli' | 'discord' | 'service_account'),
  actor_id bigint null, actor varchar(64), action varchar(64), target_kind varchar(16) ('user' | 'service_account' | 'token'),
  target_id bigint null, reason varchar(512) null, source varchar(32), details json null
```

`source` on roles and bans holds what used to be the scope idea: `local` rows come from this environment, `upstream:<provider>` rows are replaced at each sign-in through that trusted provider (identity doc section 5). Mute is a `chat` ban; moderators may only kick and mute.

### Social

```
friendships               user_id_low, user_id_high, created_at   pk (user_id_low, user_id_high)
friend_requests           from_user_id, to_user_id, created_at    pk (from_user_id, to_user_id)
blocks                    user_id, blocked_user_id, created_at    pk (user_id, blocked_user_id)
```

### Players and devices

```
player_ratings            user_id, kind varchar(16) ('all_time' | 'monthly'), rating int, matches_played int, updated_at
                          pk (user_id, kind)
player_stats              user_id pk, stats json, updated_at
player_preferences        user_id pk, color int null, side int null, map varchar(128) null,
                          starting_money int null, limit_superweapons bool null, updated_at
player_network            user_id pk, relay_region varchar(16) null, port_mapping varchar(16) null,
                          ipv4 varchar(15) null, ipv6 varchar(45) null, updated_at

devices                   id, user_id, kind varchar(16) ('machine_guid' | 'mac' | 'volume_serial' | ...),
                          value_hmac binary(32), first_seen_at, last_seen_at, last_ip varchar(45) null
                          unique (user_id, kind, value_hmac)
                          -- retention: purged 180 days after last_seen_at

session_events            id, user_id, kind varchar(16) ('start' | 'refresh' | 'end' | 'denied'),
                          result varchar(32), client varchar(32), client_version varchar(32),
                          exe_crc varchar(16) null, ip varchar(45), country char(2) null, created_at
                          -- retention: 90 days
```

`devices.value_hmac` is HMAC-SHA-256 with a per-deployment key (`Devices:hmac_key_path`). Equality lookups for ban evasion still work; a plain SHA-256 of a MAC or volume serial is reversible by brute force. The key can never rotate without rehashing, so it is created once and backed up with the database.

### Matches and stats

```
matches                   id bigint pk (kept), owner_user_id, name, lobby_type, roster_type, map_name, map_path,
                          is_official_map, vanilla_teams,          -- owner_user_id null when the owner was dropped starting_cash, limit_superweapons, track_stats,
                          allow_observers, max_cam_height, exe_crc, ini_crc, started_at, finished_at null
match_players             match_id, slot smallint, user_id null, team smallint null, side int null, color int null,
                          result varchar(16) null, details json null      pk (match_id, slot)
match_publications        match_id pk, attempts int, next_attempt_at, published_at null, last_error varchar(512) null
leaderboard_entries       period varchar(8) ('day' | 'month' | 'year'), period_start date, user_id,
                          points int, wins int, losses int                pk (period, period_start, user_id)
faction_stats_daily       day date, side smallint, matches int, wins int     pk (day, side)
                          -- optional cache; only if computing from matches is too slow
```

**Statistics and telemetry** (GitLab model: telemetry is metrics, user-facing stats derive from domain data):

- **Faction win rates** (today `daily_stats`, served by `GlobalStats`) are computed from `matches` and `match_players` (side and result). `faction_stats_daily` exists only as a cache keyed by real date, updated when a match finishes, if the query proves too slow.
- **Player and lobby peaks** (today `service_stats`, written hourly and never read) are not stored: the existing OpenTelemetry gauges `genonline.players.online` and `genonline.lobbies.active` already provide them through `/-/metrics`.
- **Connection outcomes** (today `connection_outcomes`, write-only) become the metric counter `genonline.connection.outcomes{protocol, result}`.

### Anti-cheat

```
anticheat_module_reports, anticheat_new_account_games, anticheat_probe_reports
  report_id pk (kept), user_id, match_id, ... (columns as today, snake_case)
```

### Machine tokens and settings

```
service_accounts, service_account_permissions, api_tokens      -- api-tokens-design.md
application_settings      key varchar(64) pk, value json, updated_by varchar(64), updated_at
```

Dropped with no successor: `web_sessions` (OpenIddict), `user_token_state` (OpenIddict authorizations), the old `admin`, `permissionslevel`, `banned` and `ban_*` columns.

Also dropped: `service_stats` and `connection_outcomes` (replaced by metrics) and `daily_stats` (derived from matches). They were keyed by day or hour of the year without the year, so every year overwrote the previous one.

## 3. Old → new mapping (import into prod)

| Old | New |
|---|---|
| `users.user_id, displayname, lastlogin` | `users` (id, username, last_sign_in_at); every user is imported with `state = 'active'` |
| `users.active` | **not imported**: the old service never read it |
| `users.account_type` | dropped: `Steam`/`Discord` is already recorded in `identities`; `Ghost` and `DevAccount` users are not imported (below) |
| `users.steam_id` | `identities(provider='steam')` |
| `users.discord_id, discord_username` | `identities(provider='discord')` |
| `users.google_id, google_email` | `identities(provider='google')`; email not trusted as verified |
| `users.gamereplays_id, gamereplays_username` | `identities(provider='gamereplays')` |
| `users.admin, permissionslevel` | **not imported**: printed in the validation report; staff re-granted by hand or via Keycloak groups |
| `users.banned, ban_reason, banned_by, ban_verified_by, ban_aliases` | `bans(restriction='play', source='local', created_by=null, reason=ban_reason)`; the rest into one `audit_log` entry |
| `users.elo_rating, elo_num_matches` | `player_ratings(kind='all_time')` |
| `users.monthly_elo_rating` | `player_ratings(kind='monthly')` |
| `users.favorite_*` | `player_preferences` |
| `users.relay_region, portmapping_tech, ipv4, ipv6` | `player_network` |
| `users.last_ip, client_id` | dropped (session events start fresh) |
| `user_devices.hwid_0..5, ip_addr` | `devices` rows, values HMAC'd |
| `friends` | `friendships` (pair normalized low/high) |
| `friends_requests` | `friend_requests` |
| `friends_blocked` | `blocks` |
| `user_stats_v2` | `player_stats` |
| `match_history` + `member_slot_0..7` | `matches` + `match_players` |
| `external_publication` | `match_publications` |
| `leaderboard_daily/monthly/yearly` | `leaderboard_entries` |
| `service_stats`, `daily_stats`, `connection_outcomes` | not imported: telemetry moves to metrics, faction stats rebuild from imported matches |
| `ac_reviews_*` | `anticheat_*` |
| `web_sessions`, `user_token_state` | not imported |

## 4. Import tool

- **Source:** the old production MariaDB, read only, schema version detected as today.
- **Target:** the prod environment database (must be empty). Test and dev start empty.
- **Phase 1, validate (no writes):** duplicate identities (one `steam_id`, `discord_id`, `google_id` or `gamereplays_id` on two users), display names that collide after normalization, orphaned rows, and the staff remap report (every user with `admin` or `permissionslevel` set). It also counts the `Ghost` and `DevAccount` users that will be dropped.
- **Dropped users (`account_type` Ghost or DevAccount):** their `users`, identities, devices, ratings, stats, preferences, network, friendships, friend requests, blocks, leaderboard and anti-cheat rows are not imported. Matches they took part in are kept: their `match_players` rows keep the slot with `user_id = null`, and a match they owned gets `owner_user_id = null`. Their ids are never reused. Exits non-zero until findings are resolved or waived in an import config file.
- **Phase 2, convert:** table by table in dependency order, batched, through the EF models of both sides.
- **Phase 3, verify:** row counts and checksums per mapping line, printed and written to a report; identity sequences set to max(id) + 1.
- **Keycloak file (official deployment, optional):** a Keycloak user import file with federated identity links and `go_user_id`, so people are matched to their prod account on first Keycloak sign-in.
- **Config switches:** legacy bans as local bans (default) or skipped; HMAC key path.
- **Modes:** `--dry-run` into a scratch database; refuses a non-empty target.
- **Cutover:** stop the old service, import, start the new deploy. No dual writes.
